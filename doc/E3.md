# Gas Water Heater

## Features

- Supports target temperature

## Customize

- Set the temperature precision for whole or halves (false for whole and true for halves, default by false)

  If the temperature value displayed on your water heater is twice the actual value, please set this value to true.

```json
{ "precision_halves": true }
```

- Set the temperature step (1 by default).

```json
{ "temperature_step": 0.5 }
```

## Cloud usage statistics

The local protocol does not report water or gas consumption, and not every E3
model has a cloud usage report. To expose it, open
`Settings -> Devices & Services -> Midea AC LAN -> Devices -> CONFIGURE`, enable
**Cloud usage statistics** and fill in the Midea cloud account (phone/email and
password) the appliance is bound to. The integration then polls the same
`dayReportV2` usage report the official app uses and exposes these sensors:

| EntityID                                       | Class  | Unit | Description                     |
| ---------------------------------------------- | ------ | ---- | ------------------------------- |
| sensor.{DEVICEID}\_cloud_water_usage_daily     | sensor | L    | Most recent complete day's water |
| sensor.{DEVICEID}\_cloud_gas_usage_daily       | sensor | m³   | Most recent complete day's gas   |
| sensor.{DEVICEID}\_cloud_duration_daily        | sensor | min  | Most recent complete day's runtime |
| sensor.{DEVICEID}\_cloud_water_usage_monthly   | sensor | L    | Current month's water to date    |
| sensor.{DEVICEID}\_cloud_gas_usage_monthly     | sensor | m³   | Current month's gas to date      |

Notes

- The feature is off by default; the sensors are only created when it is
  enabled. No cloud account is required for the local entities.
- Credentials come from the CONFIGURE dialog or the saved device json
  (`.storage/midea_ac_lan/<device_id>.json`): either a Midea cloud
  `cloud_access_token` (used directly) or `cloud_account` + `cloud_password`
  (plus optional `cloud_server`) to log in and refresh the token. The device
  `token`/`key` fields in that json are LAN credentials and are NOT accepted by
  the cloud report API.
- The report is written by the cloud once a day, so the daily value describes
  the most recent complete day (its date is exposed in the `report_date`
  attribute) and updates within an hour after the cloud publishes it.
- The monthly sensors are `total` meters reset at the start of the month;
  the previous month's value is exposed in the `last_month` attribute.
- The integration re-logs in automatically when the cloud token expires (the
  token is short-lived, so a stored account is required).

## Services

### midea_ac_lan.set_attribute

[![Service](https://my.home-assistant.io/badges/developer_call_service.svg)](https://my.home-assistant.io/redirect/developer_call_service/?service=midea_ac_lan.set_attribute)

Set the attribute of appliance. Service data:

| Name      | Description                                                                                 |
| --------- | ------------------------------------------------------------------------------------------- |
| device_id | The Appliance code (Device ID) of appliance                                                 |
| attribute | "energy_saving"<br/>"power"<br />"smart_volume"<br/>"zero_cold_water"<br/>"zero_cold_pulse" |
| value     | true or false                                                                               |

Example

```yaml
service: midea_ac_lan.set_attribute
data:
  device_id: XXXXXXXXXXXX
  attribute: smart_volume
  value: true
```
